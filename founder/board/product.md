# Product lens
Score: 4/10 | Vote: FUND IF
## What is strong
- สัญญาข้อเดียวชัดและขายง่าย: "เว็บร้านคุณเสร็จในวันเดียว คุยจบใน LINE" พูดได้ในประโยคเดียว และตรงกับพฤติกรรมร้านเล็กไทยที่อยู่บน LINE อยู่แล้ว
- คิดเรื่องประสบการณ์ลูกค้าครบทั้งเส้นทาง ไม่ใช่แค่ตัวเว็บ: Portal ลิงก์ส่วนตัว กรอกข้อมูล → ดูตัวอย่าง → อนุมัติ/ขอแก้ → จ่าย → ได้ใบเสร็จ มีหน้าจอครบทุกขั้น (preview/portal-1 ถึง portal-6 รวมหน้าลิงก์หมดอายุ)
- ใส่ใจส่วนที่ลูกค้ามองไม่เห็น: ขั้นงาน 8 ขั้นบังคับในฐานข้อมูลห้ามข้ามขั้น, เลขเอกสารต่อเนื่อง, กันจองซ้อนในฐานข้อมูล, เวอร์ชันย้อนกลับได้, ตรวจ 6 ข้อก่อนส่ง นี่คืองานที่มีรสนิยม
- บล็อก 16 แบบ + เทมเพลต T1–T10 คือกลไกที่ทำให้ "วันเดียว" เป็นไปได้จริง ถ้าเลือกถูก
- Claude ถูกวางเป็นผู้เสนอ คนเป็นผู้กดใช้ และสลิปมีคนยืนยันทุกใบเป็นค่าเริ่มต้น เป็นการออกแบบที่ระวังถูกจุด
- มี test 133 ข้อผ่านบน CI แสดงว่าโค้ดมีวินัย

## What would kill it (top 3, most dangerous first)
1. **ยังไม่เคยต่อบริการจริงแม้แต่ตัวเดียว และรอยต่อคือที่ที่มันจะพัง** ทุก test ใช้ LINE, Claude, Vercel, อีเมลแบบจำลอง ไม่เคย deploy ขึ้น Supabase/Vercel จริง สินค้านี้ทั้งตัวคือรอยต่อ: LINE webhook → Studio → Portal → Engine → โดเมน/SSL ของ Vercel → สลิป → อีเมล วันแรกที่ใช้จริงจะเจอสิ่งที่ mock ไม่เคยจำลอง เช่น ลายเซ็น webhook, โควตา push ของ LINE OA (บอทใช้ push ซึ่งนับโควตา ร้านที่ใช้แผนฟรีจะหมดเร็ว), DNS ของลูกค้าที่ไม่ยอม propagate ภายในวัน, ข้อจำกัดการซื้อโดเมน .co.th/.th ผ่าน Vercel, รูปสลิปจริงที่เบลอ ทุกจุดนี้ถ้าพัง ลูกค้าเห็นทันที และสัญญา "วันเดียว" แตก ไม่มี backup ไม่มี monitoring จึงจะไม่รู้ด้วยซ้ำว่าพังตรงไหน
2. **ฟีเจอร์บานเกินสัญญาหลัก** สัญญาคือ "เว็บในวันเดียว" แต่ระบบมีคิว/ตารางนัดหน้างาน จอง-เลื่อน-ยกเลิกผ่านแชท เตือนก่อนนัด ระบบบัญชี 4 ชนิดเอกสาร ลดหนี้ 3 บทบาท ซื้อโดเมน และอีเมลตามบทบาท (PR ยังไม่ merge) ทั้งที่ยังไม่มีลูกค้าสักราย ระบบจองกับการจ่ายเงินยังไม่ผูกกัน (จองแล้วไม่บังคับมัดจำ) แปลว่าแพ็ก Pro 5,990 ขายสิ่งที่ครึ่งเดียว ทุกฟีเจอร์ที่เพิ่มคือรอยต่ออีกจุดที่ยังไม่ทดสอบกับของจริง และดึงเวลาทีม 2 คนออกจากงานเดียวที่สำคัญ: ส่งเว็บดีๆ ให้เสร็จวันนี้
3. **"วันเดียว" ไม่เคยถูกพิสูจน์จากนาฬิกาจริง** SLA ส่งร่างใน 8 ชั่วโมงขึ้นกับลูกค้าส่งข้อมูล/รูป/PDPA ครบ ซึ่งร้านเล็กมักช้าหรือส่งไม่ครบ ลิงก์ Portal มีอายุ 7 วัน ซึ่งขัดกับเรื่องวันเดียวเอง ประสบการณ์ถูกส่งต่อระหว่างคนกับระบบหลายครั้ง (ลูกค้า → บอท → Owner → Builder → Claude → Builder → ลูกค้า → Accountant) ทุกการส่งต่อคือที่ที่เวลารั่ว ยังไม่รู้ว่าทีม 2 คนทำได้กี่เว็บต่อวัน

## The questions I would ask the founder
- ห้านาทีแรกของเจ้าของร้านที่ทักมาใน LINE หน้าตาเป็นอย่างไร ทีละข้อความ เขาต้องพิมพ์/อัปโหลดอะไรบ้างก่อนจะเห็นอะไรที่ทำให้ "ว้าว"
- ถ้าตัดเหลือฟีเจอร์เดียว จะเก็บอะไร และพร้อมตัดคิว/จอง/ลดหนี้/ซื้อโดเมนออกจากเวอร์ชันแรกไหม
- เคยลองทำเว็บจริงหนึ่งเว็บตั้งแต่ทัก LINE ถึงเว็บขึ้นโดเมนจริงหรือยัง ใช้เวลากี่ชั่วโมง ติดตรงไหน
- เมื่อ LINE push หมดโควตา หรือ DNS ลูกค้ายังไม่ชี้มาภายในวัน ลูกค้าจะเห็นอะไร และใครรู้
- ถ้าฐานข้อมูลหายพรุ่งนี้ (ไม่มี backup) เว็บลูกค้า ใบเสร็จเลขต่อเนื่อง และข้อมูล PDPA จะเป็นอย่างไร
- ลูกค้าส่งข้อมูลไม่ครบภายในวัน นับเป็น "วันเดียว" ต่อหรือไม่ สัญญาจริงที่บอกลูกค้าคืออะไร
- ต้นทุน token Claude 40k ต่อเว็บ ได้มาจากการวัดหรือการตั้งเป้า

## If FUND IF: the conditions
1. Deploy ขึ้น Supabase + Vercel จริง ต่อ LINE OA, Claude, อีเมล และโดเมนจริงครบ แล้วทำเว็บจริง end-to-end อย่างน้อย 3 ร้าน (ร้านเพื่อน/ฟรีได้) จับเวลาจากข้อความแรกถึงเว็บขึ้นโดเมน พร้อมบันทึกจุดที่พังทุกจุด
2. แช่แข็งฟีเจอร์: ไม่เพิ่มอะไรจนกว่าข้อ 1 ผ่าน และพิจารณาซ่อนคิว/จองออกจากแพ็กที่ขายได้จนกว่าจะผูกกับมัดจำ
3. มี backup ฐานข้อมูลอัตโนมัติ และ error alert ขั้นต่ำที่รอยต่อ (LINE webhook, Vercel domain, การส่งอีเมล) ก่อนรับเงินลูกค้ารายแรก
4. เปลี่ยนบอทไปใช้ reply แทน push ในจุดที่ทำได้ และคำนวณโควตา LINE OA ต่อร้านให้ชัด
5. เขียนสัญญา "วันเดียว" ให้วัดได้ (เช่น นับจากได้ข้อมูลครบ) และแสดงต่อลูกค้าก่อนจ่ายเงิน
