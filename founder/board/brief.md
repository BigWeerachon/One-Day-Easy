# Brief: One Day Easy

## ธุรกิจ (จาก founder/idea.md)
- สตูดิโอทำเว็บไซต์ให้ร้านค้าขนาดเล็กในไทยให้เสร็จภายในวันเดียว ลูกค้าคุยงาน ส่งข้อมูล ตรวจเว็บ และจ่ายเงินผ่าน LINE
- กลุ่มลูกค้าในข้อมูลตัวอย่าง: ร้านอาหาร คาเฟ่ คลินิก ยิม ที่พัก ร้านนวด ร้านแอร์ (ยังไม่ยืนยันว่าเป็นเป้าหมายจริง)
- ราคา (แคตตาล็อกตัวอย่าง ยังไม่ยืนยัน): Start 1,590 · Basic 2,990 (รวมโดเมน) · Pro 5,990 (มีระบบจอง) · Business 8,990 · ดูแลรายปี 2,990/ปี · แก้เพิ่ม 450/ครั้ง หลังแก้ฟรี 2 รอบ
- ยังไม่มีลูกค้าจริง ยังไม่ระบุงบ ช่องทางหาลูกค้า และคู่แข่ง
- ทีม: Owner 1 คน, Builder 1 คน, Accountant (บทบาทในระบบ) · ตั้ง SLA ส่งร่างให้ลูกค้าตรวจภายใน 8 ชั่วโมง · เป้ารอบแก้ ≤ 2 รอบต่อเว็บ · เพดาน token Claude 40k ต่อเว็บ

## ระบบที่สร้างเสร็จแล้ว (ตามโค้ดใน repo ณ วันนี้)
- **Studio (หลังบ้าน):** งานวันนี้ (คิวงานตาม SLA), กล่องข้อความ LINE, ลูกค้าและขั้นงาน 8 ขั้น (บังคับห้ามข้ามขั้นในฐานข้อมูล), สร้างเว็บแบบบล็อก 16 แบบ เทมเพลต T1–T10 พร้อมตรวจ 6 ข้อและเวอร์ชันย้อนกลับได้
- **Claude:** สรุปข้อมูลลูกค้าจากแชท · เสนอแก้เนื้อหาเว็บเป็น JSON ตาม schema ให้คนกดใช้ · อ่านสลิป
- **การเงิน:** ใบเสนอราคา/ใบแจ้งหนี้/ใบเสร็จ/ลดหนี้ เลขต่อเนื่อง · PDF ภาษาไทย · QR พร้อมเพย์ · ตรวจสลิปจากรูป 5 กฎ (ค่าเริ่มต้น: คนยืนยันทุกใบ) · ไม่ได้ตรวจกับธนาคารจริง
- **Portal ลูกค้า:** ลิงก์ส่วนตัว 7 วัน กรอกข้อมูลร้าน/รูป/PDPA → ดูตัวอย่างเว็บ อนุมัติหรือขอแก้ → จ่ายเงินแนบสลิป → ใบเสร็จ
- **Site Engine:** แสดงเว็บลูกค้าทุกเว็บตามโดเมน · ผูกโดเมนลูกค้า หรือซื้อโดเมนใหม่ผ่าน Vercel พร้อม SSL อัตโนมัติ
- **คิว & ตารางงาน:** ลูกค้าจอง/เลื่อน/ยกเลิกคิวเองผ่านแชท LINE (ภาษาไทย) · ทีมรันคิวหน้างาน · กันจองซ้อนในฐานข้อมูล · เตือนก่อนนัด
- **แจ้งเตือน:** LINE ถึงลูกค้า · อีเมลถึงทีมตามบทบาทและถึงลูกค้า (PR ยังไม่ merge)
- **ล็อกอินและสิทธิ์ 3 บทบาท** · คู่มือภาษาไทย · CI บน GitHub

## สิ่งที่ทดสอบแล้ว และยังไม่ได้ทดสอบ
- unit test 66 ข้อ · end-to-end test 67 ข้อ ผ่านทั้งหมด ทั้งในเครื่องและบน GitHub CI
- ทุกการทดสอบใช้ Postgres ในเครื่องและบริการจำลอง (LINE, Claude, Vercel, อีเมล) **ยังไม่เคยต่อกับบริการจริงแม้แต่ตัวเดียว** ยังไม่เคย deploy ขึ้น Supabase/Vercel จริง ไม่เคยมีลูกค้าจริงใช้
- ข้อมูลในระบบเป็นข้อมูลตัวอย่าง (seed) ทั้งหมด
- ไม่มีระบบสำรองข้อมูล ไม่มี monitoring/log กลาง ไม่มีการทดสอบโหลด
- ข้อจำกัดที่ทราบ: บอทส่งข้อความแบบ push (นับโควตา LINE OA) · ระบบจองกับการจ่ายเงินยังเป็นคนละส่วน (จองแล้วยังไม่บังคับมัดจำ) · สลิปตรวจจากรูปเท่านั้น

## คำถามที่ยังไม่มีคำตอบ
- ใครคือลูกค้ากลุ่มแรก และจะหาเขาได้จากช่องทางไหน ต้นทุนต่อรายเท่าไร
- "เสร็จในวันเดียว" ทำได้จริงกี่เว็บต่อวันด้วยทีม 2 คน
- ต้นทุนต่อเว็บ (เวลาคน, ค่า Claude, ค่าโฮสติ้ง/โดเมน) และกำไรต่อแพ็ก
- คู่แข่ง: ยังไม่ได้สำรวจ
