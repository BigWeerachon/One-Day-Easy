# บรีฟออกแบบ Template & Design System — One Day Easy

เอกสารนี้บอกว่าต้องออกแบบอะไรบ้างเพื่อนำเข้าระบบเทมเพลตของ One Day Easy และต้องทำตามกติกาอะไร
ดีไซน์ที่ทำตามเอกสารนี้ นักพัฒนาแปลงเป็นโค้ดได้ตรงๆ ผ่านการตรวจอัตโนมัติ และทีมหยิบไปประกอบในหน้า `/templates` ได้ทันที

> หลักการ: **นักออกแบบสร้าง "ชิ้นส่วน" → ทีม "ประกอบ" เป็นเทมเพลต → ลูกค้า "ใส่ข้อมูล"**
> ลูกค้าแก้ได้แค่ข้อมูล (ข้อความ รูป ราคา) เปิด/ปิดบล็อกที่ไม่บังคับ และเปลี่ยนโลโก้
> ลูกค้าเปลี่ยนสี ฟอนต์ หน้าตา หรือลำดับไม่ได้ ทุกชิ้นจึงต้องสวยได้เองกับข้อมูลทุกแบบ

## 1. ภาพรวมการส่งงาน

| ขั้น | ใครทำ | ผลลัพธ์ |
|---|---|---|
| 1. ออกแบบ Design System + บล็อก ใน Artifacts | นักออกแบบ | ลิงก์ Artifact |
| 2. แปลงเป็นโค้ด + เขียนเทส | นักพัฒนา | ชุดสี / คู่ฟอนต์ / หน้าตาใหม่ใน `packages/blocks` และ Engine |
| 3. ระบบตรวจอัตโนมัติ | ระบบ | ผ่าน/ไม่ผ่าน (คอนทราสต์ ข้อมูลยาว ฯลฯ) |
| 4. ประกอบเป็นเทมเพลตในหน้า `/templates` | ทีม | ร่างเทมเพลต |
| 5. ดูตัวอย่าง 3 แบบบนมือถือ + Owner อนุมัติ | ทีม / Owner | เทมเพลตเวอร์ชันที่ถูกล็อก |

**การตั้งชื่อ** (ใช้ชื่อเดียวกันในดีไซน์และในโค้ด)
- ชุดสี: ภาษาอังกฤษตัวเล็ก คำเดียว เช่น `coffee`, `chili`, `lotus`
- หน้าตาของบล็อก: `<บล็อก>/<ชื่อหน้าตา>` เช่น `hero/cover`, `menu/list`, `footer/compact`
- เทมเพลต: `R` = ร้านอาหาร, `C` = คาเฟ่ ตามด้วยเลข เช่น `R2`, `C3`

## 2. กติการวม (ใช้กับทุกชิ้น)

### 2.1 มือถือก่อน
- ออกแบบที่ความกว้าง **360px** ก่อน แล้วค่อยขยายเป็น 768px (แท็บเล็ต) และ 1280px (คอม)
- พื้นที่เนื้อหาบนคอมกว้างไม่เกิน **1080px** และมีขอบซ้าย-ขวาอย่างน้อย **20px**
- ห้ามมีการเลื่อนแนวนอนทั้งหน้า (ยกเว้นบล็อกที่ตั้งใจเป็นแถบเลื่อน เช่น `gallery/strip`)
- ทุกชิ้นต้องไม่ล้นจอ เมื่อใส่ข้อความยาวสุดตาม[ตารางในข้อ 6](#6-ชั้นที่-4--บล็อกเนื้อหา)

### 2.2 อ่านง่าย (Accessibility)
| เรื่อง | เกณฑ์ |
|---|---|
| ตัวหนังสือบนพื้นหลัง และบนพื้นการ์ด | คอนทราสต์ **≥ 4.5:1** |
| ตัวหนังสือขาวบนสีหลัก (หัวเว็บ ปุ่ม) | คอนทราสต์ **≥ 3:1** |
| ตัวหนังสือบนสีรอง (ปุ่มรอง แท็ก) | คอนทราสต์ **≥ 4.5:1** (ปัจจุบันใช้สีเข้ม `#141a2b` บนสีรอง) |
| ขนาดตัวหนังสือเนื้อหา | **≥ 16px** บนมือถือ · ตัวเล็กสุด (meta) **≥ 12px** |
| ระยะบรรทัด | เนื้อหา 1.5–1.7 · หัวข้อ 1.2–1.3 (ภาษาไทยมีสระบน-ล่าง ห้ามบีบ) |
| ปุ่มและลิงก์ที่กดได้ | สูงและกว้าง **≥ 44px** · ปุ่มติดกันเว้นห่าง ≥ 8px |
| สถานะ | ห้ามใช้สีอย่างเดียวบอกความหมาย ต้องมีคำหรือไอคอนด้วย (เช่น "หมดชั่วคราว") |
| โฟกัสคีย์บอร์ด | ทุกปุ่ม/ลิงก์ต้องมีกรอบโฟกัสที่มองเห็น |
| รูป | ทุกรูปเนื้อหามีคำอธิบาย (alt) · รูปตกแต่งไม่ต้องมี |

### 2.3 ภาษาไทย
- ใช้ฟอนต์ที่มีภาษาไทยครบเท่านั้น (ข้อ 3.2)
- ภาษาไทยไม่มีเว้นวรรคระหว่างคำ ต้องให้ตัดบรรทัดได้ทุกที่ (ระบบใส่ `overflow-wrap:anywhere` ไว้แล้ว) ออกแบบโดยไม่ถือว่าข้อความจะตัดบรรทัดตรงคำ
- ห้ามตัวพิมพ์ใหญ่ทั้งหมด หรือ letter-spacing กว้าง กับภาษาไทย
- ราคาแสดงแบบ `฿1,290` (ระบบจัดรูปแบบให้) · เผื่อความยาวถึง `฿1,000,000`

### 2.4 ประสิทธิภาพ (ให้เว็บเร็ว)
- ไม่มี JavaScript เฉพาะชิ้น (ทุกอย่างเป็น HTML + CSS ที่ server สร้าง)
- Animation ได้เฉพาะ CSS เบาๆ (transition/opacity/transform) และต้องปิดเองเมื่อผู้ใช้ตั้ง "ลดการเคลื่อนไหว" (`prefers-reduced-motion`)
- ไม่ใช้วิดีโอพื้นหลัง ไม่ใช้รูปพื้นหลังที่เป็นลวดลายขนาดใหญ่
- ไอคอนเป็น SVG เส้นเดียว (stroke) ขนาด 24×24 · ห้ามใช้ฟอนต์ไอคอน
- รูปทุกรูปมีสัดส่วนตายตัว (ข้อ 3.6) เพื่อไม่ให้หน้ากระโดดตอนโหลด

### 2.5 สิ่งที่ห้ามทำ
- ห้ามสีที่ไม่อยู่ในชุดสี (ทุกสีต้องมาจากโทเคน 5 ค่า หรือผสมจากโทเคนด้วยความโปร่งใส)
- ห้ามข้อความที่ฝังในรูป (ลูกค้าแก้ไม่ได้ และอ่านด้วยโปรแกรมอ่านหน้าจอไม่ได้)
- ห้ามองค์ประกอบที่ต้องมีข้อมูลที่ไม่มีช่องให้กรอก ถ้าต้องการช่องใหม่ให้ระบุในดีไซน์ (ข้อ 6.0)
- ห้ามดีไซน์ที่พังเมื่อไม่มีรูป

## 3. ชั้นที่ 1 — Design Tokens

### 3.1 ชุดสี (Palette)
ทุกชุดสีมี **5 ค่าเท่านั้น** + บอกว่าเป็นโหมดมืดหรือไม่

| โทเคน | ใช้ที่ไหน | ตัวแปร CSS |
|---|---|---|
| `primary` สีหลัก | พื้นหัวเว็บ (hero) ราคา ลิงก์เด่น | `--p` |
| `accent` สีรอง | ปุ่มหลัก (CTA) แท็ก ป้าย | `--a` |
| `bg` พื้นหลัง | พื้นหน้าเว็บ | `--bg` |
| `surface` พื้นการ์ด | การ์ด กล่อง | `--sf` |
| `text` ตัวหนังสือ | ข้อความทั้งหมด | `--tx` |
| `dark` (ใช่/ไม่ใช่) | ชุดสีพื้นเข้ม | คลาส `.dark` |

สีที่ระบบสร้างต่อจากโทเคน (ไม่ต้องออกแบบแยก แต่ต้องดูว่าสวย)
- เส้นขอบ = `text` โปร่ง 9–10%
- พื้น Section สลับ = `primary` 6% ผสมกับ `bg`
- Head bar = `bg` โปร่ง 88% + เบลอ

ชุดสีที่มีอยู่แล้ว (ออกแบบเพิ่มได้ ไม่ต้องซ้ำ)

| id | ชื่อ | primary | accent | bg | surface | text |
|---|---|---|---|---|---|---|
| coffee | กาแฟคั่ว | #7a4a2a | #e9b872 | #faf6f0 | #ffffff | #2b1d12 |
| chili | พริกแดง | #c8102e | #fcc419 | #fff8f0 | #ffffff | #1f1a17 |
| basil | ใบโหระพา | #2f6b3a | #f2c14e | #f5f8f2 | #ffffff | #1b2a1d |
| matcha | มัทฉะ | #4f7a3a | #e6c27a | #f7f5ee | #ffffff | #25301c |
| ocean | ทะเล | #0f766e | #f2c14e | #f3faf8 | #ffffff | #12302c |
| night | บาร์กลางคืน (มืด) | #b45309 | #c9a24a | #0e0e10 | #18181b | #f2efe8 |

**ต้องส่ง:** ชื่อไทย + id + 5 ค่า HEX (`#rrggbb`) + ผลคอนทราสต์ 3 คู่ (text/bg, text/surface, ขาว/primary)
**แนะนำ:** 8–12 ชุด ครอบคลุมโทนอุ่น เย็น ธรรมชาติ หรู และโหมดมืด 1–2 ชุด

### 3.2 ฟอนต์ (คู่ฟอนต์)
ทุกเทมเพลตใช้ **คู่ฟอนต์** = ฟอนต์เนื้อหา + ฟอนต์หัวข้อ

ฟอนต์ที่ใช้ได้ตอนนี้: `IBM Plex Sans Thai`, `Sarabun`, `Kanit`, `Prompt`, `Mitr`, `Chonburi`
- ต้องเป็นฟอนต์ไทยจาก **Google Fonts** เท่านั้น ถ้าจะใช้ตัวใหม่ แจ้งชื่อ + น้ำหนักที่ใช้ (เช่น 400, 600, 700)
- ใช้ได้ไม่เกิน 2 ฟอนต์ต่อเทมเพลต และไม่เกิน 3 น้ำหนักต่อฟอนต์
- ฟอนต์ตกแต่ง (เช่น Chonburi) ใช้กับหัวข้อเท่านั้น ห้ามใช้กับเนื้อหา

คู่ที่มีอยู่: `classic` (Sarabun + Prompt), `bold` (Sarabun + Kanit), `modern` (IBM Plex + Kanit), `friendly` (Mitr), `story` (Sarabun + Chonburi)

### 3.3 ขนาดตัวอักษร (Type scale)
| ระดับ | มือถือ | คอม | ใช้ที่ |
|---|---|---|---|
| Display (h1 หน้าแรก) | 30px | 52px | หัวข้อ hero |
| H2 | 22px | 30px | หัวข้อ section |
| H3 | 18px | 20px | ชื่อการ์ด |
| Lead | 16px | 20px | คำโปรย |
| Body | 16px | 16px | เนื้อหา |
| Meta | 14px | 14px | ข้อมูลรอง |
| Small | 12px | 12px | แท็ก |

ออกแบบปรับ scale ได้ แต่ต้องไม่ต่ำกว่าขั้นต่ำในข้อ 2.2

### 3.4 ความโค้งมุม (Radius)
- ค่าเดียวต่อเทมเพลต **0–28px** (ทีมเลือกตอนประกอบ)
- องค์ประกอบด้านในใช้ `radius − 6px` (เช่น รูปในการ์ด)
- ปุ่มและแท็กเป็นทรงแคปซูล (999px) **หรือ** ตาม radius ให้ระบุว่าแบบไหน

### 3.5 ระยะห่าง (Spacing)
ใช้สเกล 4px: `4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 88`
- ระยะบน-ล่างของ Section: 36px (มือถือ) – 64px (คอม)
- ช่องห่างระหว่างการ์ด: 16px

### 3.6 สัดส่วนรูป
| ที่ใช้ | สัดส่วน | ขนาดอัปโหลดสูงสุด |
|---|---|---|
| รูปหน้าแรก (แบบข้าง) | 4:3 | 1600px |
| รูปหน้าแรก (เต็มจอ) | ครอบเต็ม ความสูง ≤ 70% ของจอ | 1600px |
| รูปเมนู/สินค้า | 4:3 | 1000px |
| แกลเลอรี | 1:1 | 1600px |
| โลโก้ | สูง 28px ในหัวเว็บ กว้าง ≤ 120px | 600px |

ระบบครอปรูปให้อัตโนมัติ จึงต้องออกแบบให้สวยแม้รูปถูกครอปตรงกลาง

### 3.7 เงาและเส้นขอบ
- กำหนดได้ไม่เกิน 2 ระดับ: `flat` (เส้นขอบบาง) และ `raised` (เงาอ่อน)
- เงาต้องใช้สีดำโปร่งใส ห้ามเงาสี

### 3.8 ไอคอน
ต้องมีชุดไอคอนเส้น 24×24 อย่างน้อย:
LINE, โทรศัพท์, แผนที่/หมุด, นาฬิกา, ดาว, เผ็ด (พริก), ตะกร้า/สั่งอาหาร, ลูกศรขวา, ปิด (×), เมนู (☰), พร้อมเพย์/QR, รูปภาพ (ที่ใช้แทนเมื่อไม่มีรูป)

## 4. ชั้นที่ 2 — ชิ้นส่วนพื้นฐาน (Components)

ทุกชิ้นต้องออกแบบครบทุกสถานะในข้อ 9 และใช้ได้ทั้งโหมดสว่าง/มืด

| ชิ้น | แบบที่ต้องมี | หมายเหตุ |
|---|---|---|
| **ปุ่ม (Button)** | หลัก (พื้นสีรอง) · รอง (เส้นขอบ) · ขนาดปกติ 48px · ขนาดเล็ก 36px (ใช้ในหัวเว็บเท่านั้น และพื้นที่กดยังต้อง ≥ 44px) | ข้อความ ≤ 16 ตัวอักษร · มีไอคอนข้างหน้าได้ |
| **การ์ด (Card)** | พื้นการ์ด + เส้นขอบ หรือเงา · มีรูป/ไม่มีรูป | ใช้กับเมนู ชุด รีวิว เวลาเปิด |
| **ป้ายราคา (Price)** | ราคาปกติ · ราคาลด (มีราคาเดิมขีดฆ่า) | สีหลัก (โหมดมืดใช้สีรอง) · ห้ามตัดบรรทัด |
| **แท็ก (Tag/Badge)** | แท็กทั่วไป (เช่น "ขายดี") · สถานะ "หมดชั่วคราว" · "ใหม่" | ข้อความ ≤ 12 ตัวอักษร |
| **ระดับความเผ็ด** | 0–3 พริก | มีข้อความสำหรับโปรแกรมอ่านหน้าจอ |
| **ดาวรีวิว** | 0–5 ดาว (ครึ่งดาวได้) + ตัวเลข | |
| **Eyebrow** | ข้อความเล็กเหนือหัวข้อ (เช่น "เปิดทุกวัน 10:00–21:00") | |
| **ลิงก์** | ปกติ · ชี้ · โฟกัส | |
| **QR กล่อง** | กล่องพื้นขาว 160×160 สำหรับ QR LINE/พร้อมเพย์ | QR ต้องอยู่บนพื้นขาวเสมอ |
| **รูปแทน (Placeholder)** | เมื่อไม่มีรูป | หรือออกแบบให้การ์ดดูดีโดยไม่มีพื้นที่รูป |
| **ตัวแบ่ง (Divider)** | เส้นบาง | |
| **ช่องกรอก (Input)** | ข้อความ · ตัวเลข · เวลา · พื้นที่ข้อความยาว | ใช้ในหน้าสั่งออนไลน์ (ข้อ 8) |
| **ตัวเพิ่ม-ลดจำนวน (Stepper)** | − 0 + | ปุ่ม ≥ 44px |
| **ข้อความแจ้ง (Alert)** | สำเร็จ · ผิดพลาด · ข้อมูล | มีไอคอน + คำ |

## 5. ชั้นที่ 3 — โครงหน้า (Head bar, Footer, Section)

### 5.1 Head bar (แถบบน)
| ส่วน | ข้อมูล | ขีดจำกัด |
|---|---|---|
| โลโก้ (ไม่บังคับ) | รูปจากลูกค้า | สูง 28px |
| ชื่อร้าน | ข้อความ | ≤ 60 ตัวอักษร (ต้องตัด/ย่อได้บนมือถือ) |
| ปุ่มด้านขวา | "แอด LINE" หรือ "สั่งออนไลน์" (ถ้าเชื่อมระบบร้าน) | 1 ปุ่ม |

**ต้องมี:** ติดบนเมื่อเลื่อน (sticky) · พื้นโปร่ง+เบลอ หรือทึบ ·
**หน้าตาที่ออกแบบเพิ่มได้:** `header/simple` (ปัจจุบัน), `header/centered` (โลโก้กลาง), `header/bold` (พื้นสีหลัก)

### 5.2 Footer
| ส่วน | ข้อมูล |
|---|---|
| ลิงก์นโยบายความเป็นส่วนตัว (ถ้ามีบล็อก legal) | พับเปิดได้ |
| ลิขสิทธิ์ | "© ปี ชื่อร้าน · ทำเว็บโดย One Day Easy" (บังคับ) |

**หน้าตาที่ออกแบบเพิ่มได้:** `footer/compact` (ปัจจุบัน), `footer/full` (มีชื่อร้าน ที่อยู่ เวลาเปิด LINE ซ้ำอีกครั้ง)

### 5.3 Section (กรอบของทุกบล็อก)
- หัวข้อ section (H2) + เนื้อหา
- พื้นปกติ / พื้นสลับ (alt) ใช้สลับกันให้หน้าไม่จืด
- ระบุว่าบล็อกไหนใช้พื้นสลับ

### 5.4 ส่วนติดต่อ (Contact) — รวมอัตโนมัติท้ายหน้า
ระบบรวม เวลาเปิด + ที่ตั้ง + QR LINE + QR พร้อมเพย์ เป็นการ์ดเรียงกันท้ายหน้า (บล็อก hours, line, map, promptpay ไม่แสดงแยก)
ต้องออกแบบให้ดูดีเมื่อมี 1, 2, 3 หรือ 4 การ์ด

### 5.5 ป้ายตัวอย่าง (Ribbon)
ป้ายลอยมุมขวาบน "ตัวอย่าง · ยังไม่เผยแพร่" (มีแล้ว ปรับสไตล์ได้)

## 6. ชั้นที่ 4 — บล็อกเนื้อหา

### 6.0 กติกาของบล็อก
- ทุกบล็อกออกแบบได้หลาย **หน้าตา (variant)** แต่ทุกหน้าตาต้องใช้ **ข้อมูลชุดเดียวกัน** (ช่องเดียวกัน ขีดจำกัดเดียวกัน)
- ถ้าหน้าตาใหม่ต้องการช่องข้อมูลใหม่ ให้เขียนระบุในดีไซน์: ชื่อช่อง · ชนิด (ข้อความ/ตัวเลข/รูป) · ความยาวสูงสุด · บังคับไหม
- ทุกบล็อกต้องดูดีเมื่อข้อมูล **น้อยสุด** และ **มากสุด** ตามตาราง
- บล็อกที่ไม่มีข้อมูลจะไม่แสดงเลย (ไม่ต้องออกแบบกรอบว่าง)

**บล็อกบังคับ** (ทุกเทมเพลตต้องมี ลูกค้าปิดไม่ได้): หน้าแรก (hero) · LINE · เวลาเปิด (hours) · แผนที่ (map)
ร้านอาหาร/คาเฟ่ ต้องมี **เมนู** ด้วย

### 6.1 ตารางบล็อกทั้งหมด

ช่องที่มี ★ คือช่องบังคับ · ตัวเลขคือความยาวสูงสุด (ตัวอักษร) หรือช่วงค่า

**ไอเดียเพิ่ม:** `centered`, `magazine` (ตัวหนังสือใหญ่ รูปเล็ก), `stacked` (รูปบน ข้อความล่าง)

## 7. ชั้นที่ 5 — เทมเพลตทั้งหน้า

เทมเพลต 1 ชุดประกอบด้วย:

| สิ่งที่ระบุ | ตัวอย่าง |
|---|---|
| ชื่อ (ไทย) + รหัส | "ครัวไทยสีสด" · R1 |
| ประเภทธุรกิจ | ร้านอาหาร / คาเฟ่ |
| ลำดับบล็อก + หน้าตาของแต่ละบล็อก | hero/cover → menu/cards → sets/cards → reviews/quote → … |
| บล็อกบังคับเพิ่มเติม (นอกจากที่บังคับเสมอ) | — |
| ชุดสี | chili |
| คู่ฟอนต์ | bold |
| ความโค้งมุม | 16 |
| หน้าตา head bar / footer | header/simple · footer/compact |

**กติกา**
- หน้าแรก (hero) อยู่บนสุดเสมอ
- บล็อกแต่ละตัวใช้ได้ครั้งเดียวต่อเทมเพลต
- ใช้ได้เฉพาะชุดสี/ฟอนต์/หน้าตาที่ผ่านการตรวจแล้ว
- ต้องส่งภาพ 3 แบบ: ข้อมูลตัวอย่าง · ข้อมูลยาวสุด · ข้อมูลน้อยสุด (ข้อ 10) ทั้งมือถือและคอม

**แนะนำเริ่มต้น:** ร้านอาหาร 3 ชุด (ร้านข้าวแกง/ตามสั่ง · ร้านนั่งกินมีบรรยากาศ · ร้านเน้นเดลิเวอรี) และคาเฟ่ 3 ชุด (มินิมอล · อบอุ่นไม้ · สดใสถ่ายรูป)

## 11. Checklist ก่อนส่งงาน

**Tokens**

2. **Components** — ปุ่ม การ์ด ราคา แท็ก (ครบทุกสถานะ)
3. **โครงหน้า** — head bar 2–3 แบบ · footer 2 แบบ · ส่วนติดต่อ
4. **บล็อกหลัก** — hero 3–4 แบบ · เมนู 3–4 แบบ · รีวิว 2–3 แบบ · แกลเลอรี 2–3 แบบ
5. **บล็อกรอง** — ชุดคุ้มค่า · FAQ
6. **เทมเพลต** — ร้านอาหาร 3 ชุด · คาเฟ่ 3 ชุด
7. **หน้าสั่งออนไลน์ + 404**
8. (เฟสถัดไป) บล็อกธุรกิจอื่น
