## 1. ภาพรวมระบบ

```
ลูกค้า ──LINE──▶ /api/line/webhook ──▶ Studio (apps/studio) ◀── ทีมงาน (เบราว์เซอร์)
                                  │      │
                                  │      ├── Postgres / Supabase (supabase/migrations)
                                  │      ├── Claude API (สรุปแชท · แก้เว็บ · อ่านสลิป)
                                  │      └── Vercel API (โดเมน + SSL)
ลูกค้า ──เบราว์เซอร์──▶ Portal /p/<token>
ผู้เข้าชมเว็บ ──โดเมนร้าน──▶ Site Engine (apps/engine) ── อ่าน sites.config จาก DB เดียวกัน
```

| ส่วน | ที่อยู่ในโค้ด | หน้าที่ |
|---|---|---|
| Studio | `apps/studio` | หลังบ้านของทีม, LINE webhook, Portal ลูกค้า, cron |
| Site Engine | `apps/engine` | แสดงเว็บลูกค้าทุกเว็บตามโดเมน และหน้าตัวอย่างเว็บร่าง |
| Blocks | `packages/blocks` | schema ของบล็อก 16 แบบ, เทมเพลต T1–T10, PromptPay, ลายเซ็นลิงก์ตัวอย่าง |
| ฐานข้อมูล | `supabase/migrations/0001–0009` | ตาราง, trigger, RLS · `supabase/seed.sql` = ข้อมูลตัวอย่าง |
| ทดสอบ | `apps/studio/lib/*.test.ts`, `tests/` | unit test, e2e test, บริการจำลอง |

ขั้นงานของลูกค้า 1 ราย (ห้ามข้ามขั้น บังคับซ้ำในฐานข้อมูล):

```
แชทใหม่ → เก็บข้อมูล → เลือกเทมเพลต → ลูกค้าตรวจ ⇄ (ขอแก้) → ออกใบ → ชำระ → ออนไลน์ → ดูแลรายปี
                                  (พักงานได้ทุกขั้น ต้องใส่เหตุผล · กลับขั้นเดิมได้)
```

## 2. ติดตั้งและตั้งค่า

### 2.1 สิ่งที่ต้องมี

- Node.js 22 ขึ้นไป
- Postgres 15 ขึ้นไป: ใช้ Supabase หรือ Postgres ในเครื่องก็ได้ ต้องเปิดใช้ extension `pgcrypto` และ `btree_gist` ได้ (Supabase เปิดให้แล้ว)
- (ไม่บังคับ) LINE OA, Anthropic API key, Vercel token

### 2.2 ติดตั้งครั้งแรก (เครื่องนักพัฒนา)

```bash
npm install
```

```bash
cp apps/studio/.env.example apps/studio/.env.local
```

แก้ `DATABASE_URL` ใน `.env.local` ให้ชี้ไปที่ฐานข้อมูลของคุณ แล้วสร้างตารางพร้อมข้อมูลตัวอย่าง:

```bash
npm run db:seed -w apps/studio
```

สร้างบัญชี Owner คนแรก (ระบบจะถามรหัสผ่าน):

```bash
npm run user:create -w apps/studio -- you@example.com "ชื่อของคุณ" owner
```

```bash
npm run dev
```

เปิด http://localhost:3000

### 2.3 คำสั่งฐานข้อมูล

| คำสั่ง | ทำอะไร | ใช้เมื่อ |
|---|---|---|
| `npm run db:setup -w apps/studio` | รัน migration ที่ยังไม่เคยรัน (บันทึกใน `_migrations`) | production · หลังอัปเดตโค้ด |
| `npm run db:seed -w apps/studio` | migration + ข้อมูลตัวอย่าง (ข้ามถ้ามีลูกค้าแล้ว) | เครื่องนักพัฒนา |
| `npm run db:reset -w apps/studio` | ⚠️ **ลบทุกตาราง** แล้วสร้างใหม่ + seed | เครื่องนักพัฒนาเท่านั้น |

> ห้ามรัน `db:reset` กับฐานข้อมูลจริงเด็ดขาด

### 2.4 ตั้งค่าแยกตามฟีเจอร์

ฟีเจอร์ไหนยังไม่ได้ตั้งค่า ระบบจะปิดส่วนนั้นและแสดงข้อความบอก ไม่ล่มทั้งระบบ

| ฟีเจอร์ | ตัวแปรที่ต้องตั้ง |
|---|---|
| ฐานข้อมูล (บังคับ) | `DATABASE_URL` |
| LINE | `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `CRON_SECRET` |
| Claude | `ANTHROPIC_API_KEY` (และ `ANTHROPIC_MODEL` ถ้าต้องการเปลี่ยนโมเดล) |
| ตรวจสลิปอัตโนมัติ | `SHOP_RECEIVER_ACCOUNTS` / `SHOP_RECEIVER_NAMES` |
| Portal + QR | `STUDIO_URL`, `PROMPTPAY_ID` |
| ตัวอย่างเว็บ | `ENGINE_URL`, `PREVIEW_SECRET` (ต้องตรงกับฝั่ง Engine) |
| PDF | `SELLER_*` |
| โดเมน | `VERCEL_TOKEN`, `VERCEL_TEAM_ID`, `ENGINE_PROJECT_ID`, `PLATFORM_DOMAIN`, `REGISTRANT_*` |

รายละเอียดทุกตัวอยู่ใน[ภาคผนวก](#19-ภาคผนวก-environment-variables)

> **ความปลอดภัย:** ใส่ secret ใน `.env.local` หรือ Vercel Environment Variables เท่านั้น ห้าม commit และห้ามส่งในแชท

## 3. ล็อกอิน บัญชี และสิทธิ์ทีม

### 3.1 ล็อกอิน

- เข้า `/login` ด้วยอีเมลและรหัสผ่าน
- ผิด 5 ครั้งติดกัน ระบบจะล็อกอีเมลนั้น 15 นาที
- session อยู่ได้ 14 วัน

### 3.2 บัญชีของฉัน (`/account`)

- เปลี่ยนรหัสผ่าน: อย่างน้อย 10 ตัว ต้องมีทั้งตัวอักษรและตัวเลข
- สมาชิกใหม่จะถูกบังคับให้ตั้งรหัสผ่านเองตอนเข้าครั้งแรก

### 3.3 จัดการทีม (`/settings` · Owner เท่านั้น)

- เพิ่มสมาชิก กำหนดบทบาท ปิดบัญชี และรีเซ็ตรหัสผ่านได้
- เปลี่ยนบทบาท ปิดบัญชี หรือรีเซ็ตรหัส จะตัด session ของคนนั้นทันที
- ระบบต้องมี Owner อย่างน้อย 1 คนเสมอ
- ถ้า Owner ลืมรหัสผ่าน ให้รันคำสั่งนี้ด้วยอีเมลเดิม:

  ```bash
  npm run user:create -w apps/studio -- email "ชื่อ" owner
  ```

## 4. งานวันนี้ (`/`)

- **KPI:** งานที่กำลังทำ, สลิปรอตรวจ, SLA ใกล้หมด, Token ต่อเว็บ
- **แจ้งเตือน:** เว็บล่ม และงานที่ dead-letter
- **คิวที่ต้องมีคนทำ:** เรียงตาม SLA กดปุ่มในรายการแล้วจะพาไปหน้าที่ต้องทำต่อทันที
- **บอร์ดการ์ดงาน:** แสดงงานแยกตามขั้น

## 5. กล่องข้อความ (`/inbox`)

- รวมแชท LINE และช่องทางอื่น ตัวเลขสีแดงบนเมนูคือจำนวนข้อความที่ยังไม่อ่าน
- พิมพ์ตอบแล้วกด **ส่ง** ระบบจะส่งผ่าน LINE ทันที ใต้ข้อความมีสถานะ ✓ ส่งแล้ว หรือ ✗ ส่งไม่สำเร็จ
- ถ้าส่งไม่สำเร็จชั่วคราว ระบบจะลองใหม่เองผ่าน cron ถ้ายังล้มเหลว ไปกด **ลองใหม่** ในหน้า Workflow
- ข้อความเรื่องคิวที่บอทตอบเองแล้ว จะถูกทำเป็น "อ่านแล้ว" แต่ยังเห็นบทสนทนาทั้งหมด
- ลูกค้าที่ทีมเพิ่มเองยังไม่มี LINE userId จึงส่งข้อความหาไม่ได้ จนกว่าลูกค้าจะทัก OA มาก่อน (ข้อจำกัดของ LINE)

## 6. ลูกค้าและขั้นงาน (`/clients`)

- **ค้นหา/กรอง** ตามสถานะ: lead, active, care
- **เพิ่มลูกค้า:** ระบบสร้างงานในขั้น "แชทใหม่" ให้อัตโนมัติ
- **หน้าลูกค้า** (`/clients/<id>`):

    - เลือกเทมเพลต → ลูกค้าตรวจ ต้องตรวจผ่าน 6/6
    - พักงาน ต้องใส่เหตุผล
  - **สรุปจากแชท (Claude):** ดู[ส่วนที่ 9](#9-สร้างเว็บและ-claude-builder)
  - **ส่งลิงก์ Portal:** ดู[ส่วนที่ 12](#12-portal-ฝั่งลูกค้า)
  - **บันทึกโน้ต** และ **ไทม์ไลน์ event** ของลูกค้า

## 7. คิว & ตารางงาน (`/queue`)

มี 3 แท็บ: **รันคิว**, **ตารางงาน**, **ตั้งค่าการจอง**

### 7.1 สถานะของคิว

```
                ┌────────────── ยกเลิก ◀─────────────┐
รอยืนยัน(held) ─▶ จองแล้ว ─▶ มาถึงแล้ว ─▶ กำลังให้บริการ ─▶ เสร็จแล้ว
   │ หมดเวลา       │   ไม่มา ◀──┘  (ย้อนกลับ "มาถึงแล้ว" ได้)
   ▼               ▼
 หมดเวลายืนยัน     ไม่มา ─▶ มาถึงแล้ว (มาสาย)
```

| สถานะ | ความหมาย |
|---|---|
| รอยืนยัน | ลูกค้าเลือกเวลาใน LINE แล้ว ระบบกันที่ไว้ให้ชั่วคราว (ค่าเริ่มต้น 10 นาที) |
| จองแล้ว | ยืนยันแล้ว ได้เลขคิวของวัน |
| มาถึงแล้ว | ลูกค้ามาถึงหน้าร้าน รอเรียก |
| กำลังให้บริการ | เรียกคิวแล้ว |
| เสร็จแล้ว / ไม่มา / ยกเลิก / หมดเวลายืนยัน | จบแล้ว ไม่กันเวลาอีกต่อไป |

ฐานข้อมูลบังคับลำดับนี้ด้วย trigger และเก็บประวัติทุกการเปลี่ยนใน `booking_events` ซึ่งแก้และลบไม่ได้

### 7.2 แท็บรันคิว (หน้างานประจำวัน)

1. เลือกวันด้วยปุ่ม ‹ › หรือช่องวันที่ ค่าเริ่มต้นคือวันนี้ตามเวลาไทย
2. **KPI:** คิวทั้งหมด, มาถึงแล้วรอเรียก, กำลังให้บริการ, เสร็จแล้ว/ไม่มา
3. **การ์ดผู้ให้บริการ** (หนึ่งใบต่อคน/ห้อง):
   - แสดงคิวที่กำลังให้บริการ และจำนวนคิวที่รออยู่
   - **เสร็จ:** ปิดคิวปัจจุบัน
   - **เรียกคิวถัดไป:** เลือกคิวที่ "มาถึงแล้ว" ตามเวลานัดแล้วตามเลขคิว ส่ง LINE แจ้งลูกค้าว่า "ถึงคิวแล้ว" และจะไม่เรียกซ้อนถ้าผู้ให้บริการยังติดคิวก่อนหน้า
4. **ตารางคิวของวัน:** ปุ่มของแต่ละแถวเปลี่ยนตามสถานะ เช่น มาถึงแล้ว, เริ่มให้บริการ, เสร็จ, ไม่มา
   - **ยกเลิก** ต้องใส่เหตุผล ระบบส่งเหตุผลไปบอกลูกค้าทาง LINE
5. **จองคิวให้ลูกค้า** (กล่องด้านขวา):
   1. เลือกบริการ แล้วกด **ดูเวลาว่าง**
   2. เลือกเวลา เลือกผู้ให้บริการ (หรือให้ระบบเลือกคนที่งานน้อยที่สุด) และเลือกลูกค้าในระบบหรือพิมพ์ชื่อ
   3. ติ๊ก **แจ้งลูกค้าทาง LINE** ถ้าต้องการ แล้วกด **จองคิว**
   - ทีมจองให้ได้โดยไม่ติดเงื่อนไข "จองล่วงหน้าอย่างน้อย" แต่ยังต้องอยู่ในเวลาทำการและไม่ซ้อนกับคิวอื่น
6. **รับ walk-in ตอนนี้** (แสดงเฉพาะวันนี้):
   - พิมพ์ชื่อแล้วกดปุ่ม คิวจะเข้าสถานะ "มาถึงแล้ว" ทันที
   - ติ๊ก **แทรกคิว** เพื่อรับนอกเวลาที่ว่างตามตาราง ยังห้ามซ้อนเวลากับคิวอื่นของคนเดียวกัน

### 7.3 แท็บตารางงาน (รายสัปดาห์)

- แสดงจันทร์–อาทิตย์ แยกแถวตามผู้ให้บริการ เห็นเวลาเปิด วันหยุดพร้อมเหตุผล และทุกคิวพร้อมสถานะ
- คลิกหัววันเพื่อไปที่แท็บรันคิวของวันนั้น

### 7.4 แท็บตั้งค่าการจอง (Owner)

| หัวข้อ | รายละเอียด |
|---|---|
| **บริการ** | รหัส (A-Z, 0-9, _, - ยาว 2–20 ตัว · ใส่รหัสเดิมเพื่อแก้) · ชื่อ · ใช้เวลา 5–720 นาที · เผื่อหลังจบ (buffer) · จำกัดคิวต่อวัน · ราคา · ผู้ให้บริการที่ทำได้ · จองผ่าน LINE ได้ไหม · เปิดหรือปิดใช้ |
| **ผู้ให้บริการ** | คนหรือห้อง ชื่อ สี และเปิด/ปิดใช้ · 1 คนรับได้ 1 คิวในเวลาเดียวกัน |
| **เวลาทำการ** | เลือกวันในสัปดาห์ + เวลาเปิด–ปิด · ใช้กับทุกคน (ค่ากลาง) หรือเฉพาะคน · ถ้าตั้งเวลาเฉพาะคนในวันใด จะใช้แทนค่ากลางในวันนั้น · ใส่หลายช่วงต่อวันได้ (เช่น พักเที่ยง) |
| **วันหยุด / ปิดรับ** | ช่วงวันที่ + เหตุผล ทั้งร้านหรือเฉพาะคน · ⚠️ คิวที่จองไว้แล้วจะไม่ถูกยกเลิกอัตโนมัติ |
| **กฎการจอง** | เปิดจองผ่าน LINE · ช่วงห่างของเวลาเริ่ม (step) · จองล่วงหน้าอย่างน้อย (นาที) · จองล่วงหน้าได้ไม่เกิน (วัน) · กันที่รอยืนยัน (นาที) · ยกเลิก/เลื่อนเองได้ถึงก่อนนัด (นาที) · ส่งเตือนก่อนนัด (นาที, 0 = ไม่เตือน) |

**ระบบคำนวณช่วงว่างอย่างไร**

- เวลาเริ่มไล่ทีละ step นับจากเวลาเปิด
- งานต้องจบก่อนเวลาปิด (ไม่นับ buffer)
- ห้ามทับกับคิวที่ยังมีผลของผู้ให้บริการคนเดียวกัน (นับรวม buffer)
- ตัดวันหยุด เวลาที่ผ่านไปแล้ว และเวลาที่ใกล้เกิน "จองล่วงหน้าอย่างน้อย" ออก
- ถ้าบริการจำกัดจำนวนต่อวัน และวันนั้นเต็มแล้ว จะไม่แสดงช่วงว่าง
- เวลาเดียวกันว่างหลายคน ระบบเลือกคนที่มีงานรวมน้อยที่สุดในวันนั้น
- เวลาทั้งหมดคิดตามเวลาไทย (UTC+7)

**กันจองซ้อน 2 ชั้น**

1. lock รายวันตอนสร้างคิว
2. exclusion constraint `bookings_no_overlap` ในฐานข้อมูล ถ้ามีสองคนกดเวลาเดียวกันพร้อมกัน จะได้คิวแค่คนเดียว

## 8. จองคิวผ่านแชท LINE (ฝั่งลูกค้า)

บอทจะตอบเฉพาะข้อความที่เกี่ยวกับคิว ข้อความอื่นเข้ากล่องข้อความให้ทีมตอบตามปกติ

### 8.1 สิ่งที่ลูกค้าพิมพ์ได้

| ลูกค้าพิมพ์ | บอททำอะไร |
|---|---|
| `จองคิว`, `ขอคิว`, `ลงคิว`, `นัด` | ถามบริการ (ถ้ามีหลายบริการ) → แสดงวันที่ว่าง |
| `ขอจองคิวปรึกษาพรุ่งนี้ 10 โมง` | ถ้าเวลานั้นว่าง กันที่ให้ทันทีแล้วขอให้กดยืนยัน · ถ้าไม่ว่าง เสนอเวลาใกล้เคียง |
| `วันศุกร์ว่างไหม`, `15 พ.ย. มีคิวไหม` | แสดงเวลาว่างของวันนั้นเป็นปุ่ม |
| `คิวของฉัน`, `เช็คคิว` | แสดงคิวที่จองไว้ พร้อมปุ่มเลื่อนและยกเลิก |
| `ยกเลิกคิว` | ถามยืนยัน → ยกเลิก (ภายในเวลาที่อนุญาต) |
| `เลื่อนนัด`, `เปลี่ยนเวลา` | เลือกวันและเวลาใหม่ → ย้ายคิวเดิม |

**รูปแบบวันที่ที่เข้าใจ**

- วันนี้, พรุ่งนี้, มะรืน
- วันจันทร์–อาทิตย์ (ครั้งถัดไป)
- "ศุกร์หน้า" (ศุกร์ถัดจากศุกร์ที่จะถึง)
- 15/11, 15/11/69, 15 พ.ย., 15 พฤศจิกายน 2569, วันที่ 15
- เลขไทยใช้ได้ เช่น ๑๕/๑๑

**รูปแบบเวลาที่เข้าใจ**

- 10 โมง, บ่าย 2, บ่าย 3 โมงครึ่ง, 14:30, 10.30 น., 2 ทุ่ม, 4 โมงเย็น, เที่ยง
- ถ้าพิมพ์เป็นคำอย่าง "บ่ายสอง" บอทจะเข้าใจแค่ว่าเป็นช่วงบ่าย แล้วให้ลูกค้าเลือกเวลาจากปุ่ม

### 8.2 ขั้นตอนจอง

1. ลูกค้าพิมพ์ หรือกดปุ่มเลือกบริการ → วัน → เวลา
2. ระบบกันที่ไว้ตามเวลาที่ตั้งไว้ แล้วส่งสรุปพร้อมปุ่ม **✅ ยืนยัน / เปลี่ยนเวลา / ยกเลิก**
3. ลูกค้ากด **ยืนยัน** → ได้ "คิวที่ N · รหัส BK-YYMM-NNNN"
4. ถ้าไม่ยืนยันภายในเวลา cron จะปล่อยที่คืน ลูกค้าต้องเลือกเวลาใหม่
5. ระบบส่ง LINE เตือนก่อนเวลานัด และแจ้งเมื่อ "ถึงคิวแล้ว"

**กติกาเพิ่มเติม**

- บอทจำบริการและวันที่ที่คุยค้างไว้ 30 นาที ลูกค้าตอบสั้นๆ อย่าง "บ่าย 3" ได้
- ปุ่มของคิวคนอื่นใช้ไม่ได้ ระบบตรวจว่าเป็นเจ้าของคิวทุกครั้ง
- ยกเลิกหรือเลื่อนเองไม่ได้ ถ้าใกล้นัดเกินกำหนด บอทจะบอกว่าทีมจะติดต่อกลับ
- วันปิด วันที่ผ่านไปแล้ว หรือเกินช่วงจอง บอทจะบอกเหตุผลและเสนอวันที่ว่างใกล้ที่สุด
- บอทตอบด้วยการส่งข้อความแบบ push ซึ่งนับรวมในโควตาข้อความรายเดือนของ LINE OA

### 8.3 ปิดการจองผ่าน LINE ชั่วคราว

เอาติ๊ก **เปิดให้จองผ่านแชท LINE** ออกในแท็บตั้งค่าการจอง บอทจะเงียบ และทุกข้อความจะเข้ากล่องข้อความแทน

## 9. สร้างเว็บและ Claude (`/builder`)

- **แก้ทีละบล็อก** ตาม block schema · ตรวจ 6 ข้อ · บันทึกเป็นเวอร์ชัน · ย้อนกลับได้
- **ให้ Claude แก้:**
  1. พิมพ์สิ่งที่อยากแก้ แล้วกด **ขอข้อเสนอ**
  2. Claude ส่งข้อเสนอแยกตามบล็อก ระบบตรวจกับ schema แล้วแสดงเนื้อหาเดิมเทียบกับเนื้อหาใหม่
  3. คนกด **ใช้ข้อเสนอนี้** เอง
  - กดใช้ไม่ได้ถ้ามีบล็อกไม่ผ่าน schema หรือเว็บถูกแก้หลังจากขอข้อเสนอ
- **สรุปจากแชท** (หน้าลูกค้า): Claude อ่านแชทแล้วดึงชื่อร้าน ประเภท ผู้ติดต่อ เมนูและราคา เทมเพลตที่แนะนำ และ "ข้อมูลที่ยังขาด"
  - เติมเฉพาะช่องที่ยังว่าง
  - ความชอบด้านดีไซน์บันทึกเป็นโน้ตลูกค้า
- ทุกคำขอบันทึกจำนวน token เพื่อใช้กับ KPI "Token ต่อเว็บ"
- ถ้า Claude ปฏิเสธ หรือ API key ผิด ระบบแสดงข้อความภาษาไทยที่อ่านเข้าใจได้
- **ดูตัวอย่างเว็บ:** ลิงก์ไป Engine ที่ลงลายเซ็นไว้และมีวันหมดอายุ

## 10. โดเมนและ SSL

ตั้งค่าได้ที่การ์ด **โดเมน** ในหน้าสร้างเว็บ

### 10.1 ผูกโดเมนที่ลูกค้ามีอยู่แล้ว (Builder/Owner)

1. พิมพ์โดเมน เช่น `kruapadaeng.com` แล้วกด **ผูกโดเมน** ระบบล้าง `https://`, `www.` และตัวพิมพ์ใหญ่ให้เอง
2. ระบบแสดงเรคคอร์ด DNS ที่ลูกค้าต้องตั้ง: TXT สำหรับยืนยัน และ A หรือ CNAME
3. cron `/api/cron/domains` ตรวจทุก 10 นาที: ยืนยันความเป็นเจ้าของ → DNS ถูกต้อง → https ใช้ได้ → สถานะ **ใช้งาน** (Vercel ออก SSL ให้เอง)
4. ถ้าต้องการตรวจทันที กด **ตรวจอีกครั้ง** · กด **ถอดโดเมน** เพื่อเลิกใช้

### 10.2 ซื้อโดเมนใหม่ (Owner เท่านั้น)

1. พิมพ์ชื่อโดเมน แล้วกด **เช็กราคา**
2. ถ้าราคาเกิน `DOMAIN_MAX_PRICE_USD` จะไม่มีปุ่มซื้อ
3. พิมพ์ชื่อโดเมนซ้ำเพื่อยืนยัน แล้วกด **ซื้อ $X**
   - ระบบซื้อด้วยราคาที่เห็นเท่านั้น ถ้าราคาเปลี่ยนจะไม่ซื้อและแจ้งให้เช็กใหม่
   - โดเมนจดในชื่อบริษัทตาม `REGISTRANT_*`

## 11. การเงิน สลิป และ PDF (`/finance`)

### 11.1 เอกสาร

- **ออกเอกสารใหม่:** ประเภท QT (ใบเสนอราคา), INV (ใบแจ้งหนี้), RN (ต่ออายุ), CN (ลดหนี้)
  - เลขที่ต่อเนื่องแยกตามประเภทและเดือน เช่น `INV-2611-009`
  - เลขที่ออกภายใน transaction จึงไม่ซ้ำ
  - ใบเสนอราคาหมดอายุใน 15 วัน
- **PDF:** ภาษาไทย ฟอนต์ Sarabun มีจำนวนเงินเป็นตัวอักษร
  - เอกสารที่ยกเลิกหรือหมดอายุมีลายน้ำ
  - ถ้ายังไม่จด VAT จะพิมพ์ว่า "ไม่ใช่ใบกำกับภาษี"
- **ยกเลิกเอกสาร:** เก็บประวัติไว้ ลบไม่ได้

### 11.2 สลิป

- **ทาง LINE:** ลูกค้าที่มีใบค้างชำระส่งรูปมา ระบบดาวน์โหลดรูป ให้ Claude อ่าน แล้วตรวจ 5 กฎ:
  1. เป็นสลิปโอนเงินจริง
  2. ยอดตรงกับใบค้างพอดี
  3. เลขอ้างอิงไม่เคยใช้มาก่อน
  4. โอนเข้าบัญชีร้าน
  5. วันที่โอนไม่เกิน `SLIP_MAX_AGE_DAYS` และไม่ก่อนวันออกใบ
- **ผ่านครบทุกข้อ** (เมื่อเปิด `SLIP_AUTO_APPROVE=on`): อนุมัติเอง → ออกใบเสร็จ → งานขึ้นออนไลน์ → แจ้งลูกค้าทาง LINE
- **ไม่ผ่านข้อใดข้อหนึ่ง:** เข้าคิว "สลิปรอตรวจ" พร้อมรูปและเหตุผล
  - คนเลือกใบแจ้งหนี้ แล้วกด **ยืนยันรับเงิน**, **ปฏิเสธ** หรือ **อ่านใหม่**
- **อัปโหลดสลิป** (เลือกลูกค้า + รูป) หรือ **บันทึกยอดด้วยมือ** ได้ที่หน้าการเงิน
- ค่าเริ่มต้นคือคนกดยืนยันทุกใบ (ระบบยังอ่านและตรวจ 5 ข้อให้ดูประกอบ) · ตั้ง `SLIP_AUTO_APPROVE=on` เมื่อต้องการให้อนุมัติเองเมื่อผ่านครบทุกข้อ
- ยืนยันหรือปฏิเสธแล้ว ระบบแจ้งลูกค้าทาง LINE ให้เอง (ชำระครบแนบเลขใบเสร็จ ชำระบางส่วนแจ้งยอดคงเหลือ)
- ⚠️ ระบบอ่านจากรูปเท่านั้น ไม่ได้ตรวจกับธนาคาร ควรกระทบยอดกับ statement ธนาคารเป็นประจำ

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://<studio>/api/cron/booking
```

## 15. Deploy ขึ้น Vercel + Supabase

1. **Supabase:** ใช้ connection string แบบ URI รัน migration ครั้งแรก (และทุกครั้งที่มี migration ใหม่):

   ```bash
   DATABASE_URL=... npm run db:setup -w apps/studio
   ```

2. **Vercel โปรเจกต์ Studio:** Root Directory = `apps/studio` · ตั้ง env ตาม[ภาคผนวก](#19-ภาคผนวก-environment-variables) · บน serverless ใช้ Transaction pooler (port 6543) · cron ใน `vercel.json` ทำงานอัตโนมัติ
3. **Vercel โปรเจกต์ Engine:** Root Directory = `apps/engine` · ตั้ง `DATABASE_URL` และ `PREVIEW_SECRET` · ผูก wildcard `*.PLATFORM_DOMAIN`
4. **สร้าง Owner คนแรก** ด้วย `user:create` (ชี้ `DATABASE_URL` ไปที่ฐานข้อมูลจริง)
5. **LINE Developers:** Webhook URL = `https://<studio>/api/line/webhook` → Verify → เปิด Use webhook · ปิด Auto-reply ใน LINE OA Manager
6. **ตั้งค่าการจอง:** เข้า **คิว & ตารางงาน → ตั้งค่าการจอง** แล้วเพิ่มบริการ ผู้ให้บริการ และเวลาทำการ
7. **ทดสอบหลัง deploy (smoke test):**
   - ล็อกอิน
   - ส่งข้อความหา OA แล้วดูว่าเข้ากล่องข้อความ
   - พิมพ์ "จองคิว" ใน LINE
   - เปิด PDF หนึ่งใบ
   - เรียก cron หนึ่งครั้ง

### 17.3 ตัวอย่างเทสต์ใหม่

สร้างไฟล์ `tests/e2e/09-ของฉัน.test.mjs`:

```js
import { test, before, after } from "node:test";
import assert from "node:assert/strict";
import { resetDb, closeDb, closeBrowser, loginAs, act, chat, lineText, quick, val, URLS } from "./lib.mjs";

before(resetDb);
after(async () => { await closeBrowser(); await closeDb(); });

test("ลูกค้าถามวันว่างแล้วได้ปุ่มวัน", async () => {
  await lineText("Umine0000000000000000000000000001", "สวัสดี");          // สร้างลูกค้า
  const m = await chat("Umine0000000000000000000000000001", () => lineText("Umine0000000000000000000000000001", "ปรึกษา ว่างวันไหน"));
  assert.ok(quick(m).some((b) => b.data.startsWith("bk:day:CONSULT:")));
});

test("owner เห็นคิววันนี้", async () => {
  const p = await loginAs("owner");
  await p.goto(`${URLS.studio}/queue`);
  assert.equal(await p.locator(".kpi", { hasText: "คิวทั้งหมด" }).locator(".v").innerText(), "6");
});
```

**แนวทาง**

- เทสต์ต้องไม่พึ่งวันที่จริง: คำนวณวันที่จากวันนี้ เช่น "วันพุธถัดไปที่ห่างอย่างน้อย 2 วัน" ดูตัวอย่างใน `03-booking-chat`
- งานที่ทำหลังตอบ webhook (บอท, อ่านสลิป) ให้ใช้ `chat()` หรือ `waitFor()` ห้ามใช้ `sleep` คงที่
- ตรวจผลทั้งที่หน้าเว็บ ในฐานข้อมูล (`val`) และที่ส่งออกไปภายนอก (`linePushes`, `mockLog`)
- ข้อมูลตัวอย่างจาก `supabase/seed.sql`:
  - ลูกค้า c1–c9
  - เว็บ b1 (ร่าง) และ b2 Moka House (live)
  - ใบ INV-2611-008 ยอด 7,450 บาท
  - คิววันนี้ 6 คิว และพรุ่งนี้ 2 คิว
  - บริการ CONSULT, ONEDAY, PHOTO
  - ผู้ให้บริการ มิ้น และ Big
