เอกสารนี้ใช้ตอนออกแบบเทมเพลตใน Artifacts (Design) เพื่อให้งานออกแบบนำกลับมาลงระบบได้ตรงทุกค่า

## 1. โครงสร้าง 3 ชั้นของ token

| ชั้น | ชื่อ | ตัวอย่าง | ใครเปลี่ยนได้ |
|---|---|---|---|
| 1 | **Primitive**: ค่าดิบ | `color.chili.600 = #c8102e`, `space.4 = 16px` | ทีมออกแบบเท่านั้น |
| 2 | **Semantic**: ความหมาย | `color.primary`, `color.text`, `radius.card` | เลือกจากชุดที่ตรวจแล้ว ทั้งตอนสร้างเทมเพลตและเมื่อร้านเลือกสีหลักเอง |
| 3 | **Component**: ของชิ้นส่วน | `button.bg = color.primary`, `card.radius = radius.card` | ล็อกในเทมเพลต |

- ในงานออกแบบให้อ้างถึง **ชั้น 2 และ 3 เท่านั้น** (ห้ามใช้ `#c8102e` ตรงๆ ในชิ้นส่วน ให้ใช้ `color.primary`)
- ชั้น 2 คือสิ่งที่ระบบเก็บต่อเทมเพลต (`palette`, `fonts`, `radius`) และต่อเว็บ (`config.theme`)
- บนเว็บจริง Engine แปลง semantic token เป็นตัวแปร CSS ดังนี้

| Semantic token | CSS variable | ใช้ที่ |
|---|---|---|
| `color.primary` | `--p` | หัวเว็บ ปุ่มหลัก ลิงก์ ไอคอนเด่น |
| `color.accent` | `--a` | ป้าย ราคา จุดเน้น ขีดใต้หัวข้อ |
| `color.bg` | `--bg` | พื้นหลังหน้า |
| `color.surface` | `--sf` | พื้นการ์ด กล่อง ฟอร์ม |
| `color.text` | `--tx` | ตัวหนังสือทั้งหมด |
| `font.body` | `--font` | เนื้อความ |
| `font.heading` | `--hfont` | หัวข้อ ชื่อร้าน ปุ่ม |
| `radius.base` | `--r` | มุมการ์ด ปุ่ม รูป |

> Token ชั้น 2 มีแค่ 8 ตัวนี้ ถ้าออกแบบแล้วต้องการ token ใหม่ (เช่น `color.success`) ให้เขียนไว้ในหัวข้อ "ขอเพิ่ม token" ตอนส่งงาน
> อย่าใส่ค่าลงไปเอง เพราะต้องแก้ทั้ง Engine และตัวตรวจก่อน

## 2. สี

### 2.1 ชุดสี (Palette) ที่มีอยู่แล้ว

ทุกชุดผ่านการตรวจคอนทราสต์แล้ว ตัวเลขด้านล่างคำนวณด้วยสูตรเดียวกับระบบ (WCAG)

| id | ชื่อ | primary | accent | bg | surface | text | ตัวหนังสือ/พื้น | ขาว/primary |
|---|---|---|---|---|---|---|---|---|
| `coffee` | กาแฟคั่ว | `#7a4a2a` | `#e9b872` | `#faf6f0` | `#ffffff` | `#2b1d12` | 15.2 | 7.4 |
| `chili` | พริกแดง | `#c8102e` | `#fcc419` | `#fff8f0` | `#ffffff` | `#1f1a17` | 16.4 | 5.9 |
| `basil` | ใบโหระพา | `#2f6b3a` | `#f2c14e` | `#f5f8f2` | `#ffffff` | `#1b2a1d` | 14.0 | 6.4 |
| `matcha` | มัทฉะ | `#4f7a3a` | `#e6c27a` | `#f7f5ee` | `#ffffff` | `#25301c` | 12.7 | 5.0 |
| `ocean` | ทะเล | `#0f766e` | `#f2c14e` | `#f3faf8` | `#ffffff` | `#12302c` | 13.4 | 5.5 |
| `night` | บาร์กลางคืน (มืด) | `#b45309` | `#c9a24a` | `#0e0e10` | `#18181b` | `#f2efe8` | 16.8 | 5.0 |

### 2.2 กติกาของชุดสีใหม่

ชุดสีใหม่ต้องมีครบ 5 ช่อง เป็น `#rrggbb` ตัวพิมพ์เล็ก และต้องผ่านทุกข้อนี้

| คู่สี | ขั้นต่ำ | เหตุผล |
|---|---|---|
| `text` บน `bg` | **≥ 4.5 : 1** | เนื้อความอ่านออก (ระบบตรวจ) |
| `text` บน `surface` | **≥ 4.5 : 1** | ตัวหนังสือในการ์ด |
| ขาว `#ffffff` บน `primary` | **≥ 3 : 1** ตามที่ระบบตรวจ · **แนะนำ ≥ 4.5** | ตัวหนังสือบนปุ่มและหัวเว็บ |
| ตัวหนังสือบน `accent` | **≥ 4.5 : 1** | ป้ายราคา ป้าย "ขายแล้ว" |

- **ชุดมืด** (`dark: true`): ตัวหนังสือบน `accent` ให้ใช้ `bg` (สีเข้ม) แทน `text`
  ในชุด `night` สี `text` บน `accent` ได้แค่ 2.1 จึงต้องใช้ `bg` บน `accent`
- ห้ามใช้ gradient เป็นพื้นหลังที่มีตัวหนังสืออยู่บน (คำนวณคอนทราสต์ไม่ได้)
- ห้ามใช้ความโปร่งใสกับสีตัวหนังสือ ถ้าต้องการสีอ่อนลง ให้ขอเพิ่ม token `color.textMuted` พร้อมคอนทราสต์ที่วัดแล้ว
- สีสถานะ (สำเร็จ/เตือน/ผิดพลาด) **ต้องมีไอคอนและคำกำกับเสมอ** ห้ามใช้สีอย่างเดียว เช่น `✓ ส่งแล้ว`, `⚠ เบอร์ไม่ถูกต้อง`, ป้าย `ขายแล้ว`

### 2.3 ร้านเปลี่ยนสีเองได้แค่ไหน

- ร้านปรับ `primary` และ `accent` ได้ (ผ่าน `config.theme`) ระบบตรวจทุกครั้ง ถ้าไม่ผ่านจะใช้สีของเทมเพลตแทน
- ถ้าร้านเปลี่ยน `bg` หรือ `text` แล้วคอนทราสต์ต่ำกว่า 4.5 ระบบจะตัด `bg`, `text` และ `surface` ทั้งชุดทิ้ง
- ดังนั้นงานออกแบบ**ต้องยังดูดี เมื่อ primary เป็นสีอื่น** ให้ทดสอบเทมเพลตอย่างน้อย 3 สีหลัก (สีเดิม สีเข้ม สีสด)

## 3. ตัวอักษร

### 3.1 ฟอนต์ที่โหลดได้ (มีแค่ 6 ตัว)

`IBM Plex Sans Thai` · `Sarabun` · `Kanit` · `Prompt` · `Mitr` · `Chonburi`

ทุกฟอนต์ตกไปที่ `"IBM Plex Sans Thai", system-ui, sans-serif` ถ้าโหลดไม่ทัน
ฟอนต์อื่นใช้ไม่ได้ เพราะ Engine โหลดไว้เฉพาะชุดนี้ การเพิ่มฟอนต์ทำให้เว็บช้าลงทุกเว็บ

### 3.2 คู่ฟอนต์ (Font pair) ที่มีอยู่แล้ว

| id | ชื่อ | เนื้อความ | หัวข้อ | เหมาะกับ |
|---|---|---|---|---|
| `classic` | อ่านง่าย | Sarabun | Prompt | ร้านอาหารทั่วไป |
| `bold` | ตัวหนาชัด | Sarabun | Kanit | ร้านอาหารจานด่วน โปรโมชันเยอะ |
| `modern` | ทันสมัย | IBM Plex Sans Thai | Kanit | คาเฟ่ เต็นท์รถ |
| `friendly` | เป็นกันเอง | Mitr | Mitr | ขนม ของหวาน ร้านเด็ก |
| `story` | มีเรื่องเล่า | Sarabun | Chonburi | ร้านเก่าแก่ ร้านไทยดั้งเดิม |

### 3.3 ขนาดตัวอักษร (Type scale)

ขนาดอ้างอิงจอมือถือ 375px และจอใหญ่ ≥ 960px

| Token | มือถือ | จอใหญ่ | น้ำหนัก | ความสูงบรรทัด | ใช้ที่ |
|---|---|---|---|---|---|
| `text.display` | 32px | 48px | 700 | 1.25 | ชื่อร้านใน hero |
| `text.h1` | 28px | 36px | 700 | 1.3 | หัวหน้า (`/sell`, `/order`) |
| `text.h2` | 22px | 28px | 700 | 1.35 | หัวข้อ section |
| `text.h3` | 18px | 20px | 600 | 1.4 | ชื่อเมนู ชื่อรุ่นรถ |
| `text.body` | 16px | 17px | 400 | **1.7** | เนื้อความ |
| `text.small` | 14px | 14px | 400 | 1.6 | รายละเอียดรอง เวลาเปิด |
| `text.price` | 18px | 20px | 700 | 1.3 | ราคา (ตัวเลข) |

- ภาษาไทยมีสระบนล่าง ความสูงบรรทัดเนื้อความต้อง **≥ 1.6** ห้ามต่ำกว่านี้ ไม่งั้นสระชนกัน
- ขนาดเล็กสุดที่ใช้ได้คือ **14px** (ห้ามเล็กกว่านี้ แม้แต่ข้อความท้ายเว็บ)
- ช่องกรอกข้อมูลต้อง **16px ขึ้นไป** ไม่งั้น iPhone จะซูมหน้าเองตอนแตะ
- ห้ามใช้ตัวเอียงกับภาษาไทย และห้ามตัวพิมพ์ใหญ่ทั้งคำสำหรับภาษาอังกฤษในปุ่ม
- ตัวเลขราคาให้ใช้รูปแบบ `฿359,000` (มีจุลภาค ไม่ใช้ทศนิยมถ้าเป็นจำนวนเต็ม)

## 4. ความโค้งมุม

| Token | ค่า | หมายเหตุ |
|---|---|---|
| `radius.base` | **0–28 (จำนวนเต็ม)** ต่อเทมเพลต | ระบบตรวจช่วงนี้ ค่าที่นิยม 4 / 8 / 12 / 16 / 22 |
| `radius.card` | `= radius.base` | การ์ดเมนู การ์ดรถ กล่องฟอร์ม |
| `radius.button` | `= radius.base` (สูงสุด 999 สำหรับปุ่มแคปซูล) | ปุ่ม |
| `radius.image` | `= radius.base` | รูปในการ์ด |
| `radius.input` | `min(radius.base, 12)` | ช่องกรอก |

ออกแบบเทมเพลตด้วยค่า `radius.base` ค่าเดียว ชิ้นส่วนทั้งหมดใช้ตามนี้ ห้ามกำหนดมุมแยกรายชิ้น

## 6. ขนาดจอและเลย์เอาต์

| Token | ค่า |
|---|---|
| `breakpoint.sm` | 375px (ออกแบบที่ขนาดนี้ก่อน) |
| `breakpoint.md` | 640px |
| `breakpoint.lg` | 960px |
| `layout.maxWidth` | 1120px (`.wrap`) |
| `layout.gutter` | 16px มือถือ / 24px จอใหญ่ |
| `grid.cards` | มือถือ 1 คอลัมน์ · 640px ขึ้นไป 2 · 960px ขึ้นไป 3 |
| `target.min` | **44 × 44px** สำหรับทุกสิ่งที่แตะได้ (ปุ่ม ลิงก์ ช่องเลือก) |

- ต้องออกแบบ **มือถือก่อน** ทุกหน้า ทุกบล็อก แล้วค่อยขยาย
- หน้าเว็บต้องไม่มีแถบเลื่อนแนวนอน (ยกเว้น variant `strip` ที่ตั้งใจให้เลื่อน)
- ปุ่มหลักบนมือถือกว้างเต็มแถว

## 7. เงา เส้นขอบ การเคลื่อนไหว

| Token | ค่า |
|---|---|
| `shadow.card` | `0 1px 2px rgb(0 0 0 / .06), 0 4px 12px rgb(0 0 0 / .06)` (ชุดสว่าง) · ไม่มีเงา (ชุดมืด) |
| `border.width` | 1px |
| `border.color` | `color.text` ความโปร่งใส 12% |
| `focus.ring` | เส้น 3px สี `color.primary` ห่าง 2px · **ห้ามซ่อน focus** |
| `motion.fast` | 150ms ease-out (hover, กดปุ่ม) |
| `motion.base` | 250ms ease-out (เปิดคำถามแบบพับ) |

- ทุก animation ต้องปิดเองเมื่อผู้ใช้ตั้ง `prefers-reduced-motion`
- ห้าม animation ตอนเปิดหน้า (ทำให้เว็บช้าบนมือถือรุ่นเก่า)

## 8. รูปภาพ

| Token | สัดส่วน | ใช้ที่ |
|---|---|---|
| `ratio.hero.split` | 4 : 3 | hero แบบรูปข้างข้อความ |
| `ratio.hero.cover` | 16 : 9 (มือถือ 4 : 5) | hero แบบรูปเต็มจอ |
| `ratio.card` | 4 : 3 | รูปเมนู รูปรถ |
| `ratio.gallery` | 1 : 1 | แกลเลอรี |
| `ratio.logo` | ไม่บังคับ · สูงไม่เกิน 40px ในหัวเว็บ | โลโก้ |

- รูปทุกรูปต้องกำหนดสัดส่วนตายตัว (ไม่ให้หน้ากระโดดตอนโหลด)
- ข้อความบนรูป (hero แบบ cover) ต้องมีแผ่นสีทึบหรือไล่เฉดดำ ≥ 55% ใต้ข้อความ เพราะไม่รู้ว่าร้านจะใส่รูปอะไร
- ออกแบบกรณี **ไม่มีรูป** ไว้ด้วยเสมอ (ใช้สี `surface` กับไอคอน หรือชื่อเมนูตัวใหญ่)

## 9. Component tokens

ชิ้นส่วนเหล่านี้ใช้ซ้ำทุกบล็อก ค่าทั้งหมดอ้าง semantic token

| Component | Token | ค่า |
|---|---|---|
| **ปุ่มหลัก** `.cta` | bg / text / radius / ความสูง | `color.primary` / `#ffffff` / `radius.button` / ≥ 44px (แนะนำ 48) |
| **ปุ่มรอง** | bg / text / border | โปร่งใส / `color.primary` / 1.5px `color.primary` |
| **ปุ่มเล็ก** `.cta.sm` | ขนาด | 44 × 44px (เช่นปุ่ม +/− ในหน้าสั่ง) |
| **การ์ด** `.card` | bg / radius / padding / shadow | `color.surface` / `radius.card` / `space.4` / `shadow.card` |
| **ป้าย** `.tag` | bg / text | `color.accent` / `color.text` (ชุดมืดใช้ `color.bg`) |
| **ราคา** `.price` | สี / ตัวอักษร | `color.text` / `text.price` (ไม่ใช้สีแดงสำหรับราคา) |
| **ช่องกรอก** | ความสูง / ขนาดตัวอักษร / border / radius | ≥ 44px / 16px / 1px `border.color` / `radius.input` |
| **ข้อความผิดพลาด** | รูปแบบ | `⚠` + ข้อความภาษาไทยบอกวิธีแก้ |
| **ข้อความสำเร็จ** | รูปแบบ | `✓` + ข้อความว่าเกิดอะไรขึ้นต่อ |
| **หัวเว็บ** `.top` | bg / ความสูง | `color.surface` หรือ `color.primary` / 56–64px |
| **ป้ายขายแล้ว** (บล็อก cars) | รูปแบบ | ป้าย `.tag` คำว่า "ขายแล้ว" มุมบนรูป + รูปจางลง 40% |

### 9.1 สถานะที่ทุกชิ้นส่วนต้องออกแบบ

ปกติ · hover · กด · focus (คีย์บอร์ด) · ปิดใช้งาน · กำลังโหลด (`กำลังส่ง…`) · ผิดพลาด · ไม่มีข้อมูล

### 10.1 ข้อมูลที่แต่ละบล็อกต้องรองรับ (ออกแบบให้รับความยาวได้)

## 11. กติกาที่ระบบตรวจอัตโนมัติ

เมื่อทีมกด "ตรวจ" ในหน้าเทมเพลตของ Studio ระบบเช็ก 11 ข้อ ถ้าไม่ผ่านข้อใดข้อหนึ่ง Owner อนุมัติไม่ได้

1. มีชื่อและประเภทธุรกิจ
2. ไม่มีบล็อกซ้ำ และรู้จักทุกบล็อก
3. หน้าตา (variant) ของทุกบล็อกมีอยู่จริง
4. มีบล็อกบังคับครบ (hero hours line map + บล็อกของธุรกิจ)
5. บล็อกที่ตั้งเป็นบังคับต้องอยู่ในเทมเพลต
6. หน้าแรก (hero) อยู่บนสุด
7. ชุดสีและฟอนต์อยู่ในรายการที่ตรวจแล้ว
8. ตัวหนังสืออ่านง่ายบนพื้นหลัง (≥ 4.5 : 1)
9. ตัวหนังสือขาวบนสีหลักอ่านได้ (≥ 3 : 1)
10. ความโค้งมุมอยู่ในช่วง 0–28
11. ข้อมูลตัวอย่าง ยาวสุด และว่าง ผ่านกฎของบล็อก

ที่เหลือคุณอนุมัติเองด้วยตา: ดูดีบนมือถือ, ตรงกับธุรกิจ, ไม่มีอะไรล้นจอ

## 12. สิ่งที่ลูกค้าแก้ได้ และสิ่งที่ล็อก

| ลูกค้าแก้ได้ (ผ่าน Portal) | ล็อก (ทีมเท่านั้น) |
|---|---|
| ข้อความและรูปในทุกบล็อก | ชุดสี คู่ฟอนต์ ความโค้งมุม |
| เพิ่ม/ลบ/แก้ รายการเมนู รถ รีวิว คำถาม | ลำดับบล็อก |
| เปิด/ปิดบล็อกที่ไม่บังคับ | variant ของบล็อก |
| อัปโหลดโลโก้ | บล็อกบังคับ (ปิดไม่ได้) |
| ติ๊ก "ขายแล้ว" ที่รถ | ขนาดตัวอักษร ระยะห่าง เลย์เอาต์ |

เมื่อเทมเพลตได้รับการอนุมัติแล้วจะ **ล็อกเวอร์ชัน** แก้ไม่ได้ ถ้าจะปรับต้องสร้างเวอร์ชันใหม่ (เช่น `R1 v2`) แล้วย้ายเว็บทีละร้าน

## 13. รูปแบบไฟล์ `tokens.json` ที่ต้องส่ง

ส่งไฟล์นี้ 1 ไฟล์ต่อเทมเพลต ระบบใช้ไฟล์นี้สร้างเทมเพลตใน Studio และใช้เป็นต้นแบบของสกิล `ode-design-system` ในภายหลัง

```json
{
  "$schema": "ode-tokens/1",
  "template": {
    "name": "เต็นท์รถมั่นใจ",
    "business": "car_dealer",
    "palette": "ocean",
    "fonts": "modern",
    "radius": 12,
    "blocks": [
      { "type": "hero", "variant": "cover" },
      { "type": "cars", "variant": "cards" },
      { "type": "sellcar", "variant": "default" },
      { "type": "reviews", "variant": "cards" },
      { "type": "faq", "variant": "accordion" },
      { "type": "hours", "variant": "default" },
      { "type": "line", "variant": "default" },
      { "type": "map", "variant": "default" }
    ]
  },
  "newPalette": null,
  "requests": [
    { "kind": "token", "name": "color.textMuted", "value": "#4a5a58", "why": "ข้อความรองในการ์ดรถ", "contrast": { "on": "surface", "ratio": 6.9 } }
  ]
}
```

- `palette` และ `fonts` ใช้ **id** จากตารางหัวข้อ 2.1 และ 3.2
- ถ้าต้องการชุดสีใหม่ ใส่ใน `newPalette` แบบเดียวกับตาราง 2.1 (`id`, `name`, 5 สี, `dark`) พร้อมค่าคอนทราสต์ 4 คู่ในหัวข้อ 2.2
- สิ่งที่ระบบยังไม่มี (token ใหม่ variant ใหม่ บล็อกใหม่) ใส่ใน `requests` พร้อมเหตุผล ทีมจะเพิ่มในระบบก่อนแล้วค่อยใช้

## 14. ขั้นตอนทำงานใน Artifacts → ขึ้นระบบ

1. **ตั้ง token ก่อนวาด:** ในงาน Design ของ Artifacts ให้สร้าง design system จากเอกสารนี้ก่อน (สี ฟอนต์ ระยะ มุม) แล้วออกแบบด้วย token เท่านั้น
2. **ออกแบบที่ 375px ก่อน** แล้วค่อยทำ 960px
3. **ทำครบทุกบล็อก** ของเทมเพลตนั้น พร้อมสถานะ: ปกติ / ยาวสุด / ว่าง / โหมดมืด (ถ้าเป็นชุดมืด)
4. **ทดสอบสีหลัก 3 แบบ** ตามหัวข้อ 2.3
5. **ส่งงาน:** ลิงก์ Artifact + ไฟล์ `tokens.json` (หัวข้อ 13)
6. **ทีมแปลงเข้า Studio:** สร้างร่างเทมเพลต → กด "ตรวจ" (11 ข้อ) → แก้จนผ่าน
7. **คุณตรวจหน้าตัวอย่างและอนุมัติ** → เทมเพลตถูกล็อกเวอร์ชัน พร้อมใช้กับร้าน

> Artifacts เป็นที่ออกแบบและตกลงหน้าตา โค้ดของบล็อกจริงอยู่ใน Engine (`apps/engine/components/Site.tsx`)
> งานออกแบบที่ใช้ token และ variant ตามเอกสารนี้จะลงระบบได้ตรง ส่วนที่นอกเหนือจากนี้ต้องเพิ่มโค้ดก่อน
